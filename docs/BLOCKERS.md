# 阻塞收敛与最小补充信息

截至本阶段，开发不再以“没有SDK”作为笼统阻塞。无需接触硬件即可完成的部分已拆出：

| 项目 | 已有证据/可独立推进 | 真机闭环还缺什么 |
|---|---|---|
| SDK取得与集成 | 官方固定1.9.2 AAR；按厂商空白项目集成指引接入独立只读APK；用户确认Android13 | 具体系统构建及真机运行；公开/商业分发范围另核实，不阻塞本次私有台架开发 |
| G12输入API | `KeyChannels` GET返回int[]；与H16监听区分 | 硬件采样序号/时间、有效位、断连缓存/重播语义；通道实测 |
| GR00接口 | 官方V1.1手册区分SBUS pin6和透传pin27/29 | 用户实际模块/底板/固件、UART逻辑电平及串口配置，不能用5V供电推断 |
| 飞控控制语义 | 固定Copter4.7.1源代码与隔离SITL可验证 | X9实际固件标识/UID/参数，含厂商补丁差异 |
| 跨设备互斥 | 单一权威原型、独立进程竞争/重放/停止测试 | 所有控制入口受约束的真实拓扑；独立主SBUS健康/操作者确认 |
| Android生命周期 | 真SDK只读应用onPause停止、清空数据，超时/断开停止并需手动重试；21项契约断言 | 用户自行安装后验证实际系统权限、后台/崩溃/休眠、SDK重连 |
| 失效安全 | 记录默认覆盖超时、接收器失效、释放和恢复语义 | 原配置下隔离台架时序；本阶段保持disarmed，不验证飞行failsafe动作 |

当前最少需要用户提供三组信息；不需要令牌或私钥：

1. **实际设备清单**：G12已知Android13，还缺系统构建号（只读APK会显示）；GR00模块和底板型号/固件、接线和串口配置；X9只读导出的固件标识、UID及RC/串口/failsafe/围栏参数。尚无导出不阻塞只读APK交付，不能为采集而擅自连接/发送。
2. **SDK输入契约**：厂商关于KeyChannels源端采样/断连缓存的说明或联系人。官方集成指引支持本次私有台架应用集成；公开仓库没有LICENSE不等于“禁止一切使用”，也不证明可公开/商业再分发SDK。若出现新的SDK协议，先展示具体条款、版本和接受动作，未确认前不接受或代签。当前未出现、未接受新协议。
3. **仲裁落点**：能否增加独立空端网关覆盖所有MAVLink入口，以及实际接管/交还开关与主操作者确认方式。若必须保持双串口直入原版X9，则强制跨设备排他仍无法由Android单独保证；固件方案需另立分支和授权范围。

上述是完整控制交付的输入，并非要求用户补齐后才开发只读APK。只读应用和台架验收步骤见 [SDK_BENCH](SDK_BENCH.md)。用户已授权开发与交付APK，仍未授权助手安装、真实飞控控制、解锁、刷写或飞行。外部SDK和签名私钥继续不入库。
