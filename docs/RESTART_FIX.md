# 摇杆采集停止后再次开启：修复候选版

2026-10-17，用户进一步确认触发条件为“点击停止后再次开启会出现 code=101 timeout”，与对频无关；当前目标限定为摇杆读取和启停稳定性。

安装包：[私有预发布 v0.3.1](https://github.com/unununnnn/g12-mavlink-control/releases/tag/v0.3.1-serial-bench)，同时提供发送版0.3.1和只读版0.2.1。代码提交 `0fe0496465a70866e55d8ba0b22097131f63a35b`；[CI 39026980391](https://github.com/unununnnn/g12-mavlink-control/actions/runs/39026980391) 构建、lint及APK验证成功（发送版lint 0错误/17警告）。下载后SHA256与构建报告一致，DEX已核实包含新连接封装。详见[交付证据](evidence/restart-20261017.json)。

## 证据与边界

- 0.3.0 与 0.2.0 共用相同的 `SkydroidBackend` 和 GET `RemoteControllerKey.KeyChannels`。旧普通停止直接调用 `disconnectRC()`，下次开始调用 `connectToRC()`。
- 固定官方 RCSDK1.9.2（AAR SHA256 `e5977ba3292246bcee026defdb8563a18adc9d5573fdfb20a6880ee469f0fde2`）的 `TimeoutException` 字节码使用错误码101。
- [官方 Demo 固定源码](https://gitee.com/skydroid/rcsdk-demo/tree/d9c6bcab8bb9993cd16f117c01a7601dce10ea6a) 中 `HomeActivityForJava` 在 onCreate 初始化/连接，onDestroy 断开；README 的1.8.0历史记录提及断开后重连问题。历史记录不证明1.9.2的本次具体底层缺陷。
- 初始检查考虑端口占用；用户补充的停止/重启触发条件使排查转向连接生命周期。没有遥控器日志或原生助手源码，**没有在本机复现物理 code101，也没有证明厂商内部根因或与原生助手完全等价**。

## 改动

sender 0.3.1、readonly 0.2.1 共用 `RetainedReadBackend`：

1. “停止采集”立即清空通道、失效会话、停止后续GET；发送版同时停止发送并关闭数传管道。前台保留 SDK 输入连接与监听；暂停期间监听数据全部丢弃。SDK自身通信仍存在，不能称为无线静默。
2. “再次开始”复用连接。若旧GET尚未完成，先排空该回调，再发新GET；旧值和重复回调不得恢复新会话。排空未完成时最多等5秒，之后停止并断开。
3. “断开SDK / 释放端口”、后台、锁屏及当前采集错误仍完全断开。完整断连后的 SDK 重连可靠性仍需单独真机验证；此候选版没有把这一项宣称已解决。
4. 恢复读取不会恢复发送；输入时效、目标配置、明确开始、电脑回显、10秒限制等保护保持原样。新鲜的回调仍不能证明源端硬件新鲜度。

## G12复测（用户手动进行）

1. 保持飞控断开，关闭其他占用SDK的App。测试包使用临时CI调试签名；若系统提示签名冲突，需先卸载同包名旧测试版再安装，手工映射需重新填写。本次不自动安装。
2. 打开0.3.1，开始读取，逐轴确认原始值实时变化。先不打开数传、不开始发送。
3. 点击“停止采集与发送（保留SDK连接）”，确认通道清空。再次开始，确认数值随新动作变化。连续20轮，包含快速点击，以及停止后等待5秒再开始。
4. 另测“断开SDK / 释放端口 → 开始”、退后台/锁屏后返回再开始。两组与普通停止分开记录；若仅这组仍101，说明完整断连重连路径还需处理。
5. 如仍失败，记录包版本、系统构建号、按钮路径、首轮能否读取、失败轮次/约几秒后及完整错误。现有界面显示系统信息；无需提供凭据。强行停止后重新打开能否恢复也单独记录。

验收标准：普通停止/再读20轮无101；恢复后只显示新GET数据、发送始终保持停止。后台/显式释放后的重连结果另列，不把前者通过推广为所有SDK生命周期已通过。
